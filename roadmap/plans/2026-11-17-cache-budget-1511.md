# Keep a pool's cache within one host budget

Issue: #1511.

## Design

The controller sends current cache policies on heartbeats, including pools with
no queued jobs. An older controller sends none, which disables maintenance.
The agent's existing reconciliation tick runs maintenance independently of
runner creation and of placement. A failed inventory or measurement defers
cleanup and is reported rather than taken as permission to delete.

One non-zero `cache.size_limit` covers a pool's package entries, all retained
tool image generations and the Actions cache service on that host. Package and
tool entries are disposable, removed oldest first only while no container uses
the pool's cache and no create or tool fill is in flight. A backend gate closes
the gap between the idle check and a new local start. The service receives the
remaining budget through its own locked eviction API, never by deleting its
files behind its index. Changing a limit reaches running services without an
agent restart. This is an idle-time ceiling, not a filesystem quota: live jobs,
open transfers and a pool with no idle window can exceed it temporarily.

Measurements accompany service counters on heartbeats. Host views expose the
package, tools and service bytes, measurement time and deferral reason; cards
show the total without opening Details. Missing data stays unknown.

`StateDir()` still determines the active shared folder. For a non-root Linux
service whose home is `/var/lib/zoomies`, its default can be
`/var/lib/zoomies/.config/zoomies/shared`; that is an active supported layout,
not evidence of abandoned data. Maintenance bounds tools and service data in
that active folder, independently of an absolute package-cache source. No
unidentified historical folder is migrated or removed automatically: changing
a path requires draining runners and checking mounts first.

## Validation

Regression tests must cover cleanup after jobs finish without a new create,
live policy changes, a combined package/tools/service budget, active jobs and
tool fills, failed inventory and measurement, symlink roots, restart discovery,
heartbeat propagation and absent telemetry. Run focused race tests, UI checks,
contract regeneration and CI before merging. Live-host validation remains
separate from these tests; no host data is touched by this implementation task.
