# audit-2026-11-21.md: the handoff for plans 012 to 031

Written 2026-11-21 against commit `8ce1be3` (the drift check every plan
runs). This is the context plans 012 to 031 were cut from: what was audited,
what was found, what was left out, and the rules every one of those plans
shares. Each plan under `plans/` is the unit of work; this file is the map
and the shared rule book, so read the section "Rules for every plan" before
starting any of them.

## How the audit was run

Seven parallel read-only sweeps (authentication and the HTTP surface; the
store; the controller, scheduler and events; the agent, backends, cache
service and providers; the installer, updater and backups; Eli repair, the
model boundary and the Git worker; lean code, the UI and the edge worker).
Every finding below was then checked by the advisor against the cited code.
Findings marked *reproduced* were also shown with a throwaway test or script
kept outside the repository.

Expected load assumed: one controller, a few to a few dozen hosts, tens to
low hundreds of runners at once, thousands of jobs a day, a handful of
operators. CI jobs are untrusted code.

## Rules for every plan

These apply to plans 012 to 031 and are not repeated in each.

### Before the first command

Run `make build-nogui` once in a fresh checkout. `internal/api` embeds a
build product, and plain `go build`, `go vet` and `go test` fail without
the placeholder that target writes.

### Commands

| Purpose | Command | Expected on success |
| --- | --- | --- |
| One test | `go test -race -count=1 -run TestName ./internal/pkg/` | pass |
| A package | `go test -race -count=1 ./internal/pkg/...` | pass |
| The prose tests | `go test -count=1 ./internal/docs/...` | pass |
| Full suite | `make test` | exit 0 |
| Format | `gofmt -l <changed dirs>` | no output |
| Vet | `go vet ./<changed pkg>/...` | no findings |
| Lint | `make lint` | exit 0 |

### Conventions held by tests or review

- British spelling in prose and comments (behaviour, authorisation).
- No em dash characters anywhere, and never a spaced double hyphen used as a
  dash. Tests in `internal/docs` fail on both. Commands in fenced blocks are
  exempt.
- Comments explain why, not what: name the failure being designed out.
- Tests are table-driven, standard library `testing` only, and named as
  sentences about behaviour (`TestOpenCreatesTheDatabaseDirectory`). Stores
  in tests are `:memory:` with an injected clock (`store.Options.Now`).
- SQL is written only in `internal/store`. Package boundaries are held by
  tests; never loosen one to make a change fit.
- Error messages are written for a person to act on.
- Commit messages are imperative sentences in plain prose, sentence case, no
  prefix. Each plan gives its message.

### How to work

1. Run the plan's drift check. If an in-scope file changed, compare the
   "Current state" excerpts with the live code; a mismatch is a STOP.
2. Write the failing test first and watch it fail for the reason the plan
   gives. A test that passes before the fix is testing the wrong thing.
3. Make the smallest change that turns it green. Add no layers, options or
   configuration the plan does not name.
4. Run the plan's verification, then `make test`.
5. One commit per plan (a plan with parts says so). Do not push or open a
   pull request unless the operator said to.
6. Update the plan's row in `plans/README.md`.

### Eli repair plans (014, 015, 024, 026)

The root `AGENTS.md` requires reading
`roadmap/eli-repair-implementation-handoff.md` before changing Eli repairs
and updating it in the same pull request. For each of these plans add a
dated section to that file recording the actual scope, the validation
results, the pull request link and that the next unfinished step is
unchanged, and add a row to its "Validation and PR ledger" table. These are
corrective changes, not slices.

### STOP conditions shared by every plan

Stop and report back, and do not improvise, when:

- The code does not match a plan's "Current state" excerpt.
- A step's verification fails twice after a reasonable fix attempt.
- The fix seems to need a file the plan lists as out of scope, a schema
  migration the plan does not name, or a loosened boundary test.
- An existing test fails and the plan does not say its expectation changes.

### Fixed afterwards

Fifteen of the findings above were fixed in a second pass, each with a test that
failed first, and are no longer open:

- Restore now compares the manifest's digest for every backup, before the
  integrity check (`checkDigest` in `internal/backup/restore.go`).
- `/oauth/authorize` is limited to thirty kept requests a minute per address,
  answered with `temporarily_unavailable` to the client's own checked redirect.
- Changing a password and confirming it to turn two-step off take one of the two
  Argon2 slots, as sign-in does (`takePasswordCheck` in `internal/auth/auth.go`).
- `gitfetch.Remove` leaves symbolic links alone when it clears read-only bits.
- A re-joined host's queue is dropped with its old registration
  (`c.queues.forget` in `internal/controller/agents.go`), so a task for a runner that
  no longer exists is not handed to the machine joining now.
- A credential probe no longer moves `installations.updated_at`, the key of the
  GitHub client cache, so the probe that runs for every installation every few
  minutes stops throwing away the client it just used (`SetInstallationHealth`).
- A held job whose first news after its review is `in_progress` moves its queue
  boundary on the way to running, so the review is not reported as queue wait.
- `PruneJobs` chooses its batch once instead of twice under the writer (16% faster
  on the benchmark in the commit message).
- The process backend kills a finished runner's group when it reaps the runner
  (`releaseRunner` in `internal/backend/process_unix.go`).
- The Docker client's retry after learning the daemon's API version runs under the
  caller's context, so the answer it returns can still be read.
- The Active jobs panel and a run's job list lay the frames that arrive during a
  read over its answer (`web/src/lib/frame-layer.ts`), and `fleet.optimistic` rolls a
  refused change back only if the row is still the change.
- Migration 0146 adds the two partial indexes the per-pass runner reads need: the
  fleet read is 81% faster and the pool read 88% faster past 12,000 removed runners.
- The systemd units, the launchd plist and the compose file keep an operator's
  paths whole (spaces, `%`, `$`, XML and YAML characters, line breaks refused).
- A merge attempt is bound to the host its task was queued to, and only that host
  may pull its repository or answer it (`bind` and `assignedTo` in
  `internal/controller/eli_merge_attempts.go`). An unqueued attempt is open to
  nobody; an id that holds nothing is "not here" to every host.
